# AGENTS.md

Purrwall is a multi-chart price wall for every Hyperliquid market. It is a
static React + TypeScript app: the browser talks to Hyperliquid's public API
directly, and a small Cloudflare Worker (`worker/`) serves the build plus the
sync, feedback and trend-glyph routes.

Read [docs/architecture.md](docs/architecture.md) before changing code: the
module map, the data-layer rules, the Hyperliquid API behaviour the code
depends on, and how to verify a change.

## Commands

```bash
npm ci
npm run dev      # Vite dev server on http://localhost:5173 (PORT overrides it)
npm test         # vitest: pure logic, no DOM, no network
npm run lint     # oxlint
npm run build    # tsc -b + vite build + release check (fails the build on findings)
npm run perf     # cold-start budget against the built dist/ (headless Chrome)
npm run preview  # serve dist/
```

## Before every commit

- `npm run lint`, `npm test` and `npm run build` pass.
- UI changes are checked in a real browser: console clean, every cell reaches
  live, then the change's own checks (docs/architecture.md → Testing and
  verification).
- Changes to the data layer (`src/lib/hl/`), the chart lifecycle
  (`src/components/ChartCell.tsx`) or the startup path also pass
  `npm run build && npm run perf`. Each perf run hits the real API — wait a
  minute between runs.

## Invariants

docs/architecture.md → Invariants lists twelve rules; each guards a bug that
was fixed once. Code comments cite them as "Invariant N": keep the numbering
and append new rules at the end. The ones changes most often run into:

- All REST goes through `src/lib/hl/info.ts`; all candle I/O in ChartCell goes
  through `src/lib/hl/formulaFeed.ts`. A formula id (`=…`) never reaches
  Hyperliquid (Invariants 5 and 11).
- A WebSocket candle subscription for an id Hyperliquid doesn't know closes
  the shared socket for every chart. Ids are checked against `coinKindOf()`
  in `src/lib/hl/types.ts`.
- renderQueue keys are per bar (Invariant 1). The market catalog is updated
  only through `mergeCatalog`, and effects key on values, never on catalog
  objects (Invariant 12).
- Keyboard handlers ignore IME composition (Invariant 7).

## Conventions

- TypeScript strict. Match the surrounding code; comment only constraints
  that aren't obvious from the code, and say why the code is the way it is
  rather than how it came to be. Commit messages say what changed and why.
- No new runtime dependencies without a strong reason. Today there are three:
  react, react-dom, lightweight-charts.
- English in code, identifiers, comments, log messages, docs and commit
  messages. The UI ships in English and Chinese, so every user-visible string
  needs both: the dictionaries in `src/lib/i18n.tsx`, the language blocks in
  `DocsModal.tsx`, the inline EN/ZH pairs in `FeedbackModal.tsx` and
  `App.tsx`, both halves of a changelog entry.
- User-facing copy says what a feature does, plainly. It makes no assurances
  ("we never…", "rest assured", "read-only"); if a behaviour needs defending,
  change the code.
- Displayed numbers never visibly truncate — hide lower-priority chrome
  instead. The market picker mirrors Hyperliquid's own selector; keep it
  aligned.
- The production Content-Security-Policy allows one external origin,
  `api.hyperliquid.xyz`. A new network destination, third-party script or
  persistent identifier starts with an issue.
- `src/lib/hl/spotOverrides.json` and `spotSelector.json` are generated by
  `scripts/sync-spot-overrides.mjs`. Never edit them by hand.
- A change to a data-layer assumption updates `scripts/api-canary.mjs` in the
  same change (Invariant 10).
- Release notes: a user-visible feature prepends one bilingual entry to
  `src/changelog.ts` (id = release date `YYYY-MM-DD`, suffix `b` for a second
  entry that day). Fixes, refactors and copy changes add none.
- Branches are `feat/<slug>`, `fix/<slug>`, `chore/<slug>`. A pull request
  follows `.github/PULL_REQUEST_TEMPLATE.md`: what and why, how it was
  tested, screenshots for UI changes. Every push to `main` deploys
  purrwall.xyz.

## TradingView attribution

The charts are TradingView Lightweight Charts (Apache-2.0; see `NOTICE`), and
every surface that renders a chart must show a link to TradingView. The
topbar carries one at every width (the compact `.attribution-nw` link at
≤ 900px), so wall cells keep the canvas logo off; the canvas `attributionLogo`
is on wherever the topbar link isn't visible — `?mini=1` windows, the expanded
cell, the list view's chart card. A new chrome-less mode needs one or the
other. Before adding a topbar control, measure `.topbar` overflow at a 641px
viewport in English: an overflow there is invisible and pushes the link off
screen (Invariant 8).
